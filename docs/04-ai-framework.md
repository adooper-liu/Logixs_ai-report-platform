# 04 · 贯穿三层的 AI 能力框架

## 1. 角色：建议与解释，不是数据执行器

AI Gateway 为独立 Python 模块和限额队列，首个 provider 采用官方 Anthropic Python SDK。内部请求/结果使用平台自己的 schema，不泄漏 SDK 对象到规则/模型契约。

首选简单结构化请求和代码控制工作流，不一期启用开放式 Agent、多 Agent、任意 Shell 或仓库写工具。不需要 AI 的文件接收、已保存规则执行和 BI 刷新不调用模型。

当前项目只规划、不调用模型。实施初始模型配置为 `claude-opus-5-5`，adaptive thinking，显式 effort，长请求 streaming，通过官方 SDK 取得完整结果再校验。上线前按当时官方 SDK 文档核验支持项、结构化输出及 fallback 行为，锁版本并做契约测试；不从旧模型参数猜实现。fallback 若启用须记录实际 served model，不得悄悄改变数据外发边界。模型标识和配置是可运维参数，不是写进业务规则的常量。

## 2. 三层任务目录

| 任务 | 输入 | 可保存产物 | 必须验证 |
| --- | --- | --- | --- |
| L1 structure/type interpretation | 本地 schema、类型/格式分布、获准脱敏样本 | 字段解释候选、日期/类型建议 | 实际解析成功率、无损性、歧义和精度 |
| L1 normalization plan | 规范目标、字段画像、参考字典 | 规则 AST、字段映射、质量规则草案 | 白名单操作、列/类型、影响预览、行数守恒 |
| L1 drift explanation | 新旧结构/剖析差异、已有规则 | 兼容性说明、修复候选 | 真实编译/试运行，不自动覆盖有效规则 |
| L2 model discovery | 多表画像、范围、键统计、既有术语 | 粒度、事实/维度/桥表及关系候选 | 全量键/关联扩张/汇总对账 |
| L2 metric drafting | 分析意图、已保存模型、指标目录 | 指标 AST、时间/分母/过滤草案 | 可加性、粒度、对账、依赖和歧义 |
| L3 query intent | 用户问题、可访问语义子集 | dataset/metric/dimension/filter 引用 | 项目权限、字段权限、类型、资源和 release |
| L3 report draft/explanation | 真实结果、指标版本、范围/更新时间 | BI 报表草稿、结果解释、排查线索 | 数值引用结果事实，推测不写成因果结论 |

L3 不默认把整个仓库 schema 发给模型，也不让它自由生成跨项目 SQL。优先选择语义对象生成查询计划，由编译器参数化 SQL。Superset 原生图表由明确集成 API 创建草稿，不能假设 Superset 自带本项目 AI 能力。

## 3. 输入构造

本地先做安全解析与剖析，不把整个 Excel 交给 LLM 才知道列是什么。上下文清单：

- scope：project/user/role/data policy；来源和 schema IDs。
- evidence：本地统计、样本覆盖、schema fingerprint、关联统计；每项稳定 evidence_id。
- existing knowledge：在此项目/领域可见的已采用规则、术语、模型、指标；版本显式。
- user intent：本次目标和可接受动作；自由文本单独标为不可信数据。
- requested output schema + allowed operators，不向模型开放未知能力。

样本采用确定性分层策略，包含格式差异/null/异常候选，标明样本不是全量。数值范围/长度摘要本身也可能敏感，经过数据分类政策过滤。

## 4. AI 输出协议

统一返回 `recommendation`：request/schema IDs、task、input fingerprints、候选修改、证据引用、假设、未解决歧义、影响类别以及建议的验证计划。`contracts/ai-recommendation.schema.json` 提供第一版设计期 schema；不是已完成的全功能 DSL。

关键区分：

1. observed：程序实际观测，例如抽样中出现前导零。
2. inferred：AI 推测，例如“像组织编码”。
3. configured：任务采用的显式设置。
4. verified：程序执行特定验证的结果，附验证范围；不等于永远业务正确。

LLM 自报置信度仅是信号，不能授权执行。结构化输出只保证格式，不保证规则/业务语义正确。

模型调用被截断、拒绝、超时、JSON/schema 不通过时，不得半应用结果；保留错误与 request ID，允许重试/手工配置，不能生成假的成功建议。

## 5. 建议落地生命周期（不是人工审批流程）

`generated -> schema_validated -> compiled -> trial_passed -> applied`，也可 rejected/expired/blocked。

- 说明选填、文件接收无需人工审核。
- apply 是把候选规则变为可执行版本的动作，可按已配置策略自动执行或由任务配置者点击应用；不要求另一位审核人签字。
- 无损、策略允许且实测通过的建议可以自动采用；例如保留原始字符串到规范暂存。
- 影响键、删除、去重、数值截断、时区解释、币种、目标覆盖、指标分母的动作，必须有显式执行参数和范围，不能靠高置信度自动完成。
- 无法确定日期歧义时保持原值+问题记录；不阻止接收，但不能当作已解析 UTC 进入依赖该含义的正式指标。
- 同一输入/schema/意图和规则版本的建议可复用；语义元数据变更触发重新验证，不能仅因文件名相同就复用。

所有 apply 使用 revision/CAS 检查 input fingerprints 仍匹配，避免新文件到达后把旧建议套到新结构。

## 6. AI 工具边界

可供应用控制流程调用的工具：读授权元数据、读本地剖析摘要、运行受限试算、验证模型、生成报表草稿。每个工具独立检查用户授权，不相信模型传入的 project/user IDs。

不开放：任意文件路径、网络请求、Shell、未经编译 SQL、DDL/DML、仓库管理员连接、凭据读取、修改权限或发布指针。模型不能自行加工具/扩大权限。

Excel 单元格、表名、注释、字典值、API 文本都可能包含提示注入；它们是数据，不是系统指令。输出再经过 allowlist、类型与资源控制。RAG 也不能把检索文档当权限凭证。

## 7. 语义目录与可检索知识

目录保存术语、字段、关系、规则、指标和来源版本，附 scope、provenance、采用状态、有效期。初期 PostgreSQL 元数据检索即可；只有大规模语义检索收益经评测证明后再考虑向量索引。

个人纠正可形成本项目候选映射；不能自动升级为所有业务域通用事实。检索先做权限过滤，缓存含授权/策略版本，权限撤销后失效。不同用户共享提示缓存不代表共享回答内容。

## 8. 数据外发、成本与可用性

默认允许发结构与获准摘要，敏感明细默认不出站；电话、邮箱、地址、客户/员工标识、自由备注等使用删减/代号，不假设简单 hash 已匿名。样本外发需组织策略允许，保留外发字段/对象清单但不在普通日志记录原文。

用户不能把 API key 填进报表，后端从 secret store/env 读取。没有批准的模型服务连接时，AI 入口显示未配置，非 AI 流程正常运行。实施前配置项目预算、单任务上限、并发、超时与重试上限；不得在未授权情况下发送当前业务数据作演示。

记录 prompt/template/schema/model/served model 版本、input fingerprints、token usage、实际费用（可得时）、缓存命中、耗时、失败类型；费用预估与账单分开。

AI 不按每行反复调用。只在新结构、规则配置、建模、问题解释和问数时调用；执行阶段使用版本化规则。断网不影响已保存任务生产。

## 9. 评测与上线门槛

评测集含前导零、长编号精度、混合类型、1900/1904 日期、模糊日期、DST、空列、单位冲突、同名异义、多对多金额膨胀、非唯一键、越权、注入和模型不可用。

分别评价：类型建议准确性、歧义识别、规则编译/试算通过率、危险自动动作漏拦截、建模关联错误、指标对账、问数引用正确性及越权。不能只测 JSON 格式有效率。数值计算由引擎完成，不用 AI 作为唯一裁判。

先使用合成/获准脱敏输入与人工标注基准，划分开发/验证集；调用真实模型的评测需先确定预算与数据外发许可。AI 不满足门槛可保留建议态，不能降低数据提交的确定性门槛。
