# 07 · 实施路线与验收

## 1. 实施策略

按整体三层设计、纵向切片实现。当前交付为规划/项目骨架，不把目录存在等同模块完成。不接入 V6，不默认复制真实业务数据，不安装或启动云服务。

“说明选填、无需审核”贯穿各阶段。自动质量门槛和必要执行参数不是人工作业审批，不能为方便演示退回登记工作流。

工期仅作规划：假设 2 位有 Python/数据工程经验的工程师、前端支持和可用业务样例，P0-P5 约 12-20 周；单人通常更长。环境、SSO、数据隐私、源接口和指标歧义可能改变工期。每阶段先验收再扩，不以日期承诺替代证据。

## 2. 阶段

| 阶段 | 建议周期 | 主要交付 | 明确完成条件 |
| --- | --- | --- | --- |
| P0 独立基础 | 1-2 周 | 独立包锁/Compose、Postgres/Redis/BlobStore、账号/项目、契约/API骨架、CI | 新机器可启动；不用旧项目路径/环境；schema/权限/依赖扫描测试通过 |
| P1 接入规范闭环 | 3-4 周 | 多文件/多 sheet/目录、PG只读抽取、原始留存、manifest、画像、规则DSL、质量、幂等staging/提交、运行UI | 两输入任务有缺失/空批次/重复/范围语义；崩溃重试不重复入仓；原始可追溯 |
| P2 AI 规范助手 | 2-3 周 | 授权上下文、类型/格式/映射建议、结构化输出、试运行、采用、AI记录/预算 | 歧义不乱猜；AI停用已保存任务继续跑；无任意代码/越权；合成评测达标 |
| P3 AI 建模与指标 | 3-4 周 | grain/keys/relations、模型/指标契约、dbt编译、join对账、版本/血缘、语义目录 | 一对多金额不膨胀；跨域模型分离；同输入/版本可重现；指标分母可核对 |
| P4 发布与 AI 报表 | 2-3 周 | ReleaseBundle、原子切换/回退、Superset集成、语义问数、报表草稿 | 半成品不可查；发布ACK丢失可恢复；AI/BI同权限；报告标明release与时点 |
| P5 试点加固 | 1-4 周，可部分并行 | API接入器、增量/删除/迟到完善、SSO、压测、灾备、告警与运维 | 获准样本持续运行；故障/权限/恢复演练通过；容量边界公开 |

P1 数据库适配器第一种是 PostgreSQL；MySQL/SQL Server 按实际来源优先级扩展，不声称通用 DB 连接字符串即可替换。API 一期接口从 P0 预留，P5 完成真实分页/限流验收；若 API 是首要来源，可把其前移并等量后移非必需功能。

P2 的建议仅在配置时产生；P3/P4 共享相同 AI 网关，不建立三个独立聊天系统。数据量增长后再根据证据评估 CDC/ClickHouse/湖仓/Kubernetes，不预先作为必需组件。

## 3. 首个可运行纵向切片

使用全新合成“销售”数据而非 V6：

1. 一次任务接收订单 CSV + 明细 XLSX（明细可分两个文件），产品字典可选。
2. 本地画像识别编码/金额/日期歧义；AI 只产生类型/规则候选。
3. 采用明确的编号文本化、Decimal、日期规则，试算保留异常行。
4. 规范数据入 PostgreSQL staging；run manifest 与错误表可查。
5. 定义订单/明细粒度，验证一对多关联，生成按日期/类别的数量和金额。
6. 合格后一个 release 发布，Superset 只读展示。
7. 再交新批次，复用规则/模型；故意缺少明细、重复投递、加入错误日期，验证失败不切换当前 release。
8. 不补充任何业务说明、不安排审核人，流程仍可执行；真正影响计算的日期解释/目标写入模式必须明确。

随后用合成客服数据（工单+事件）复用同引擎，验证未把订单、物流字段写死。

## 4. 系统测试矩阵

| 维度 | 样例与期望 |
| --- | --- |
| 文件 | 损坏/宏/压缩炸弹、重复表头、多sheet、半上传、长数字，安全拒绝或明示问题 |
| 类型 | 前导零、金额溢出、小数locale、1900/1904、DST、模糊日期，不静默损失 |
| 批次 | required缺失、可选旧版本、合法空范围、同hash不同范围，manifest准确 |
| 清洗 | input/accepted/quarantine/filter计数守恒；相同版本确定性复现 |
| 增量 | 同timestamp多行、迟到、重复、删除、checkpoint提交失败，规则明确 |
| 模型 | 非唯一键、多对多、有效期重叠、distinct/ratio、币种，错误可定位 |
| 发布 | 多表一致、并发发布CAS、事务中断、ACK丢失、回退，上一版可用 |
| 权限 | 跨项目对象/AI上下文/问数/缓存/导出越权全部拒绝 |
| AI | schema错、refusal/timeout、注入、过期建议、危险动作、预算耗尽，不伪成功 |
| 运维 | Redis丢失、Worker崩溃、磁盘满、恢复备份、迁移回退，状态可恢复 |

基础框架测试不等于 AI 效果测试；AI 结果测试使用独立标注评测，外部调用先确定数据许可与费用预算。

## 5. 非功能验收

性能数据在 P1/P3 以约定机器、文件结构、行列规模、并发和查询类型压测后给出，不写没有测量的“千万行秒级”。必须报告峰值内存、磁盘临时量、P95 耗时、吞吐、失败恢复时间。

试点目标包括：错误不丢行、不可恢复失败不发布、每个报表可定位release/规则/输入；安全测试不泄露秘密；新结构不能静默破坏旧模型。备份 RPO/RTO 为计划指标，P5 实测后才可标达成。

## 6. 当前未实施清单

没有后端/前端服务、接入 Worker、清洗执行器、dbt 模型、AI 请求实现、Superset集成、真实数据迁移、定时任务、生产基础设施。当前机器可读示例/验证器只保证规划包内部一致，不替代以上实现。
