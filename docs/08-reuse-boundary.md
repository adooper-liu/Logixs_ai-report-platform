# 08 · 原项目复用边界

## 1. 独立性

参考项目：`D:\包裹物流时效`。新项目：`D:\ai-report-platform`。

本次只读评估旧文件，未复制旧运行数据、密钥、账号、虚拟环境、V6 程序或业务数据库。没有调用旧服务作为依赖，也不在新项目配置旧项目绝对路径作为运行前提。

这是一份提取计划，不代表以下能力已经在新项目实现。提取代码时在 `provenance.json` 记录源文件、hash、提取日期、修改说明与测试，不直接批量复制整个工作台。

## 2. 可复用部分

| 原位置 | 可复用内容 | 必须改造的地方 |
| --- | --- | --- |
| `governance_workbench/registry/workbooks.py` | XLSX归档边界检查、外部关系过滤、表头位置、shared strings、损坏文件测试思路 | 目前仅表头读取，不支持全量画像；完善XML/资源隔离与恶意样本测试；移除物流ALIASES与“批准”措辞；评估专门解析库，不作为已审计安全实现 |
| `.../registry/services.py` | 原始对象独立存放、checksum、CAS冲突检测、不可改写历史版本和批次幂等思想 | 拆除Django模型耦合、单文件/本机路径/SQLite及审核历史设计；引入stream/manifest/DAG/租约/warehouse发布 |
| `.../registry/tests.py`、`test_optional_definitions.py` | 合成XLSX、CSRF、对象范围、重复文件、未知字段不阻断接收等测试案例 | 重写为新接口测试，不复制用户/数据库fixtures；加入内容推断与多来源故障测试 |
| `.../browser_smoke.py` | 临时独立存储、真实浏览器驱动、错误与移动端检查方式 | 重写新UI流程、容器环境和测试账号；不依赖旧地址或服务进程 |
| `数据治理/adapters.json` | 接入输出envelope、定位/业务键分离、快照/增量、来源切换验收思想 | 只提取通用字段和原则；移除V6对象/批准流程及领域约束 |
| `数据治理/tools/validate_governance.py` | ID引用、重复配置、范围/路径限制、禁止静默改变指标等验证原则 | 不复制旧权威配置和V6 AST/SQLite核对；按新schema重新实现编译校验 |
| `数据治理/README.md` 的通用原则 | 原始不覆盖、粒度明确、身份分离、维度作用域、版本、可追溯 | 去掉以旧治理JSON为唯一权威及强制审核的条款；新权威为平台版本对象 |

## 3. 明确不复用

- `脚本/店铺指标_V6.py` 及其专用加工、关联、日历、补值、分母算法。
- V5/V6的专用字段、七国配置、物流ALIASES、物流身份/指标作为通用模型。
- 当前 Excel、衍生结果、profile统计、真实业务记录、原SQLite结果库。
- 工作台 `.runtime`、`.django-secret`、账号、上传文件、服务配置与现有虚拟环境。
- 来源业务说明必须补齐/审核后才能继续的流程；当前旧项目已取消该要求，新平台仍不恢复。
- 一文件一来源、只比表头不看内容、仅用文件名判身份的主流程。

## 4. 提取顺序和验证

1. 保持原项目只读；选具体函数/测试，不把整个旧包加入 `sys.path`。
2. 写新接口和测试，再以源hash记录待提取代码。
3. 使用新项目的合成销售+客服样例通过通用性测试。
4. 检查源代码中无旧根目录、WMS/物流专有常量、旧DB连接或密钥依赖。
5. 旧实现安全边界仅供参考，需新项目威胁建模和测试；不因曾经通过测试就宣称安全。
6. 需要真实样本时单独授权、脱敏、独立存放，不能把所有旧Excel顺手导入。

## 5. 复用成功的定义

原始留存、规范规则、任务状态和发布机制可服务不同业务域，且新项目可在没有原项目目录的机器上独立启动。这比复制页面或包装 V6 更能证明复用有效。
