# ADR-0001 · 平台基础与边界

状态：拟采用，实施阶段按技术验证更新。日期：2026-11-06。

## 决策 A：模块化后端，而非微服务集合

Django+DRF控制面，Celery隔离数据/AI任务，React工作台。模块可独立测试，执行契约与HTTP无关。避免FastAPI/Django双栈和每个功能独立服务带来的认证、状态、部署成本。

代价：大型任务不能占Web进程，必须有worker资源边界；单库跨模块修改要遵守版本契约。出现独立扩容或安全需求时再拆网关/执行服务，不先拆完整分布式平台。

## 决策 B：PostgreSQL共享仓库，DuckDB仅任务内执行

PostgreSQL提供事务、多人查询、权限、发布一致性；Parquet用于原始规范中间数据，DuckDB/Polars处理有限任务。拒绝共享SQLite/.duckdb承担公司多人报表。

代价：大规模分析上限需实测。扫描量/并发/延迟超目标且索引/分区/汇总无法满足时，评估ClickHouse或湖仓；保留connector、manifest、规则和语义接口，仍需引擎兼容测试，不能承诺无成本切换。

## 决策 C：AI建议，编译器与引擎执行

AI输出schema约束候选，试运行后按策略应用，已有任务不再每行调用AI。拒绝直接执行AI任意Python/SQL和用自报置信度授权覆盖。

代价：要维护规则/模型DSL及语义校验；复杂需求初期不支持时明确报错，不悄悄把自由代码塞进DSL。专家SQL后续是独立受限能力。

## 决策 D：无强制业务审核，但技术门槛不可猜

来源说明和业务备注可空，文件持续接收。执行模式、关联键、时间转换、覆盖范围等只在操作确实需要时要求明确。角色控制“谁能做”，自动测试控制“能否安全执行”，不是所有文件都要另一人签字。

没有配置目标写入策略时原始可留存、规范可暂存，不擅自覆盖正式目标。

## 决策 E：指标契约单一权威，Superset作为展示

平台模型/指标版本编译到SQL/dbt和BI数据集，不在Superset和平台同时手工维护同一指标。AI问数选择语义对象而非任意库表。

代价：需要集成与同步、BI变更漂移检测；一期限制通过平台管理的数据集编辑范围，不能把禁止按钮当全部安全。

## 决策 F：warehouse事务为发布权威

ReleaseBundle固定全部依赖，仓库事务切换active指针；control异步同步，通过outbox与对账恢复。拒绝跨两个库假装原子提交，也不直接覆写BI当前表。

代价：必须实现ACK丢失恢复、缓存/release绑定和历史保留。单条查询一致不等于Superset整页多查询同时一致，严格整页需要固定release。

## 决策 G：独立新项目、选择性提取旧能力

不fork整个物流工作台，不接入V6业务算法。原项目只读供通用函数/测试提取，新仓库无旧路径依赖。

## 决策 H：不预设全能基础设施

一期不要求Kafka、Spark、Airflow、Kubernetes、向量库或多Agent。Celery只处理任务消息，平台DAG、outbox、lease和幂等提交需自己实现，不能把队列当可靠工作流全部能力。

若DAG规模/回填/运营复杂度明显增长，评估成熟编排器替代；保持Run/Input/Output协议，不改变业务规则权威。每次新增组件都要有具体问题、运维责任和性能收益证据。
